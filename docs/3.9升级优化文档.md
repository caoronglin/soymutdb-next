## 1. 总目标

以保留数据库产品契约（`public_id`/`internal_id` 边界、assembly/release/provenance 语义、external/internal 双站隔离）为前提，完成三件事：

1. **前端统一到 Pro v6 栈**：React 19 + Umi Max 4 + antd 6 + ProComponents v3，统一 `apps/web`、`apps/admin`、`apps/jbrowse`。
2. **公共门户按线框对齐**：首页模块顺序、五个搜索工具页、结果列顺序、新标签页行为、响应式与双语，均按已批准参考线框实现，并让内容可由 Admin 配置。
3. **交付链可验收**：把"脚本已写、平台未实跑"的基线推进为在真实 Docker / PostgreSQL / ClickHouse / MinIO / 浏览器上可判定的交付，产出不可变静态制品与原子发布/回滚能力。

**非目标**：不重做后端权威数据模型或 API 业务语义；不改数据库权限、发布、assembly、缓存契约；不引入第二个权威存储（不用 SQLite 走完整开发路径）；不上传可执行 JS / 任意模板 / 未净化 HTML；不做多目标同时发布；不重设计 MCP 或无关分析流程。

## 3. 不可违反的基线契约

这些条款跨全部文档一致，任何实现都不得弱化：

- **身份边界**：突变体有稳定的公开 `public_id` 与私有 `internal_id`，**不得从任一推导另一**（baseline-development `:23`）；匿名以 internal ID 查询不得泄露存在性，internal 检索授权必须在 API 服务端执行，前端隐藏不构成授权（`:300-301`）。
- **assembly 语义**：v4/v5 是独立坐标命名空间；基因查找键至少为 `(assembly, accession)`；**未指定 assembly 的查询必须按 assembly 分组或返回可判定歧义，不得静默选默认版本**（baseline-development `:24`）；v4↔v5 等价只能来自带 provenance 的显式 crosswalk（`:25`）。
- **双站隔离**：`external`/`internal` 只能显式选择，禁止依据 host/IP/cookie/UA 推断（`:22`）；两套制品的 origin、CORS allowlist、缓存、SW 命名空间、hashed assets 不得复用（`:172`）；任何 internal 数据不得进入 external 的 HTML/JS/JSON/manifest/source map/SW（react-pro-v6 `:35`）；`noindex` 不是访问控制（baseline-development `:171`）。
- **存储职责**：PostgreSQL 权威（身份、关系、release、assembly、权限、工作流状态、审计）；ClickHouse 只作可重建的分析投影，不签发公开身份、不决定可见性；MinIO 对象默认私有；Redis 可丢弃（`:15-18`）。
- **缓存键**：公开搜索缓存键必须含 site variant、release、assembly、实体类型、query、filters、分页/cursor；internal 结果用私有缓存（`:26`）。
- **URL 为真源**：结果视图以查询参数为唯一真源，保证可分享、可刷新还原（public-web-layout `:119`），结果查询仅在参数校验通过后执行（`:120`）。
- **发布语义**：发布是单一权威指针切换；任一必需组件（搜索/API/JBrowse/BLAST/下载/内容快照）未就绪则整体拒绝，不做部分发布（`:169`）；静态页内嵌 release ID，水合请求携带它，避免静态页静默查询到别的数据集（`:179`）。
- **凭据**：只存在于服务端环境或 secret manager；页面定义与 TSV 文件不能提供它们（public-web-layout `:169`）；PR 流水线不得持有发布凭据（baseline-development `:174`）。
- **工具链**：`.cnb.yml` 是交付单一事实来源，GitHub workflow 仅镜像且 job body 只调 `scripts/`；Node/pnpm/Python/uv pin 必须一致（`:412`）；不得静默改 pin。

## 4. 公共门户（apps/web）

### 4.1 首页

模块顺序固定为（public-web-layout `:39-43`）：① 桌面 2:3 网格，左侧至多五条最新动态，右侧 3–6 图 carousel；② 五个任务入口，顺序 Gene ID / Physical Location / JBrowse 2 / BLAST / Primer Design；③ 已净化的 CMS 内容块。2026-09-29 核对：代码 `antd-home.tsx` 的 `TOOL_ENTRIES` 此前把 Primer Design 排在 BLAST 之前，与本节（及 `public-web-layout:42`）相反，现按本节顺序修正；前两项（Gene ID / Physical Location）为主入口，其余三项保留卡片入口。

已移除项：hero 搜索与统计条（`:45`）—— 2026-09-29 在代码中**实际**移除，此前本节声称已移除但 `antd-home.tsx` 仍渲染 `role="search"` 输入区，属文档与代码不符；品牌 intro 的 `<h1>` 与可选 CMS hero 图保留（无障碍与 SEO 需要）；**数据库入口条**（`SOYMUTDB DATABASE` eyebrow + `SoyMutDB 数据库` 标题 + `查询数据库` 链接 + 突变系/基因/变异三卡片），2026-09-29 移除，理由是它从不在批准结构内（`:47`）。

### 4.2 搜索工具页（2026-09-29 固化的路由架构规则）

`/search/{genes,location,gbrowse,blast,primer}` 各自是**独立页**，渲染自己的标题、表单与结果表；**SHALL NOT** 渲染门户 hero、全局搜索框、联邦来源开关或聚合结果列表——那些只属于 `/search`（`:51-55`）。这是路由架构规则而非样式偏好：`/search` 是渲染 `<Outlet />` 的父路由，历史上因此把门户内容塞给了每个子页（`:57`）。

各页规格：

- **Gene ID**（`/search/genes`）：assembly 下拉（显示默认标记，随发布增长）+ gene ID 输入（placeholder 示例取自当前 assembly）+ 搜索按钮；提交在新标签页打开参数化 URL；结果 6 列顺序 = Genome assembly / Chromosome / Position / Mutation feature / Gene ID / JBrowse 2 action（`:67-80`）。
- **Physical Location**（`/search/location`）：assembly + chromosome + start + end；同 6 列，每行链到 JBrowse 2（`:86`）。
- **BLAST**（`/search/blast`）：类型下拉仅 `blastn`/`blastp`；参考序列类型 = assembly version；输入接受 FASTA；结果含 genome assembly / query sequence ID / coverage / E-value / gene ID / JBrowse 2 动作，**每行两个独立动作**（`:96-103`）。
- **Primer Design**：保留现有 region 与 pasted-sequence 两种模式（`:107`）。

校验规则（`:195-200`）：空 Gene ID/FASTA 提交前拒绝；位置区间需已选 assembly 与 chromosome、`start >= 1`、`end >= start`；BLAST 需校验类型与 FASTA 结构；assembly 加载失败禁用依赖动作；loading/empty/error 显式且不得把示例数据当真实结果。

2026-09-29 补充的两条 assembly 作用域契约（实现在 `apps/web/src/lib/search-assembly.ts` 与两页路由，回归在 `lib/search-assembly.test.ts`、`routes/search/tool-pages.test.tsx`）：① 深链给出的 assembly 不可判定时（未知名称/ID）**不得静默回退到默认版本**，页面显示 `search.assemblyUnavailable` 且不发查询；② 位置区间的 start/end 必须是安全整数，`NaN`/非整数直接拒绝。两条均为 DB-CORE-3「不得静默选默认版本」在 UI 侧的落地。此外结果表与 JBrowse 2 深链现携带 `release` 参数，避免静态页静默查询到别的数据集（baseline-development `:179`）。

### 4.3 页脚与字体（admin-editable-footer-search-font）

- Admin 可编辑双语 contact/copyright 与分组导航，复用按变体、带版本的 `system_settings`，**不新增表**（`:77`、`:125`）。
- 链接目的地只允许两类：恰以单个 `/` 开头的站内路径，或无内嵌凭据的绝对 HTTPS URL；`javascript:`/`data:`/`http:`/protocol-relative 一律服务端拒绝（`:49-54`）。
- `tel:`/`mailto:` 只在值通过校验后生成，"绝不把未校验值插入 `href`"（`:43`）。
- 字体：仅公共 React 站加载 `HarmonyOS-Sans-SC-Regular.woff2`，`font-display: swap`，不 preload、不加载 Medium/Bold，保持 16px/1.65（`:113-118`）。
- 性能门禁：LCP 回归 ≤10%、CLS ≤0.1 且增幅 ≤0.02；无法测量则不得声称已验证（`:120`）。

### 4.4 UI 质量整改（portal-ui-quality-remediation）

覆盖 `apps/web` 活跃路由：`/compare`（改全宽响应式卡片网格、移除嵌套 `70vh` 滚动）、`/search`（描述换行而非静默截断）、`/sra`、`/analytics`、`/analyses/*`、`/browser` missing-context、`/news/$slug`（中文缺失时提示"展示英文原文"，不机器翻译）。字号下限：主文本/链接 ≥14px、次级 metadata ≥12px（`:53`）。新增 React 可见文案守卫（`:62-64`）。

## 7. 数据发布与搜索 IA

主链（data-publishing-and-search-ia）：7 类导入（FASTA/GFF3/VCF/BLAST DB/Seed/Expression/Homolog）→ Release → 原子发布/回滚。

- 导入状态机 `uploading → validating → ingesting → ready → published → rolled_back`（`:48-50`）；发布状态机 `draft → validated → ready → published → rolled_back`（`:55`）。
- 每个转换服务端校验，UI 只提交 `stage.x.completed`（`:58`）；验证失败不能 ingest，数据集未全 ready 不能发布（`:59`）；幂等 `idempotency_key` 且 dispatch 与 outbox 原子提交（`:60`）。
- 大文件经 MinIO 分片直传，API 只签发预签名会话，"不穿 FastAPI 内存"（`:29`）。
- 搜索契约：`SearchResultItem` 增加 `url`（前端路由而非 API 路径）与 `by_type`（`:95`）；统一 `cursor/next_cursor/has_more/total_count`，`total_count` 为 null 时隐藏总数（`:97`）；结果整行可点击，缺失 URL 用禁用态而非 `#`（`:100`）。

## 8. 本体控制平面与多物种（中远期）

- **本体控制平面**：PostgreSQL 为治理权威，Redis 只做缓存/锁/限流，不承载科学事实或发布真相（`:37`）；原始本体与制品是不可变 artifact（`:38`）；内部搜索与外部搜索**不共享结果、错误、缓存、比较资格或版本语义**（`:39`）；公开投影以版本化 field allowlist 为**主安全边界**，敏感字段扫描只是 defense-in-depth（`:223`）。顺序固定 A0 → A1 → B-pre-ADR → B → C → D → E → F，其中 A0 是硬闸门：证据完成前禁止生产迁移、写入切换与 publication 实现（`:50`）。
