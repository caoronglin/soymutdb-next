## Recent Checkpoint History

### 2026-09-29 - Search tool pages decoupled from the portal hero

- User supplied the approved wireframes for 基因号（ID）搜索 and 物理位置搜索 and asked for those two to be finished first.
- Root cause found: `apps/web/src/routes/search.tsx` is a **parent** route that renders the portal hero, the global search box and `<Outlet />` (line 216), so every child route (`/search/genes`, `/search/location`, `/search/blast`, `/search/gbrowse`, `/search/primer`, `/search/tools`) inherited a full screen of unrelated portal content above its own heading and form.
- Fixed with a conditional render in `search.tsx` rather than by moving the file: `routeTree.gen.ts` is generator-owned (`// This file was automatically generated by TanStack Router`) and no generator command exists in the repo, so restructuring the route tree was not safely reproducible.
- `search.test.tsx` mock extended with `useRouterState`; the mock must apply `select` — returning raw state handed the component an object where it expects a pathname, which failed 2 tests until corrected.
- Evidence: web suite **61 files / 324 tests passed**; `tsc --noEmit` clean; artifact rebuilt (`max build` + `generate-static-routes` 27 documents + `finalize-csp` + `gen-sw`); headless Chromium confirms `/search` still renders h1「探索 SoyMutDB」 while `/search/genes` renders **0** h1 nodes and its own h2.
- Backend chain verified by direct API calls: `/api/v1/genes/assemblies/2/chromosomes` returns Gm01–Gm20, and `/api/v1/genes?assembly_id=2&chromosome=Gm01&start=1&end=2000000` returns records.
- **尚未验证**：在浏览器里真正提交这两个表单（结果表格渲染、新标签页行为、Gbrowse 跳转），以及中文界面下的列头与提示文案。
- Open differences against the supplied wireframes, awaiting the user's call: 物理位置搜索 renders three controls (assembly select + chromosome select + start/end inputs) as the 2026-08-14 design specifies, whereas the wireframe shows one combined「染色体号:起始-终止」box; 基因 ID 输入 accepts multiple IDs (one per line) whereas the wireframe shows a single-line field.
