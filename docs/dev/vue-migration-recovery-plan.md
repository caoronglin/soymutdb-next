## 目标与事实基线

公共站的 React 基线是 `d3904c2105f34e5d74f3ae3a163d6b25f075bf64`（Vue 切换提交 `25c32e499` 的父提交）；管理端的 React 基线是 `2004c25c61d850f15335dcc8329d0649930c35a4`（Vue 切换提交 `53a65a90d` 的父提交）。`v2.1.0` 已在 Vue 切换之后，不能充当 React 验收基线。

当前两个 Vue 产物均包含 CSS；在本机浏览器中，公共站 `flex/grid` 和管理端登录页 384px 宽度实际生效。公共站与管理端的 `style.css` 在切换时丢失了 React 版的 `@theme` 语义色映射，因此 `bg-background`、`text-foreground` 等类无法生成。视觉退化还来自首页、导航、管理端路由和工作流的大幅删减，不是一个样式文件开关可以解决的。

目标是让 Vue 成为可验证的 React 功能继任者，同时保留当前 Vue 已改进的双站边界、公开标识、组装版本、发布版本、API 权限和 CSP 约束。视觉参考使用迁移前 React 源码与仓库已有截图；数据库搜索入口、筛选结果、详情和来源信息始终排在营销内容之前。

**当前工作树状态**：此前并行代理留下的源码改动按用户要求保留，但未完成集成和验收。下表中的“已观察”指本轮审计时的文件或浏览器事实；部分文件此后已经被代理修改，执行者必须先重新测量，不能把审计结论直接当作当前构建通过的证明。本文件只规定后续工作，不宣称下列功能已经修复或端口已经切换。

## 硬性约束

1. **范围与现有改动**：本轮只维护方案。后续执行须保留当前未提交改动、未追踪字体和历史视觉证据；先辨认保留的半成品，再分区实施。不得以清理目录为由删除未知来源或仍被引用的文件。
2. **数据库权威性**：PostgreSQL 是实体身份、权限、发布及工作流唯一权威；ClickHouse 仅作分析投影，MinIO 存对象，Redis 可丢弃。多实例之间不建立共享权威库，也不通过前端直接连接数据库。
3. **身份、版本与公开边界**：公开突变体只用稳定 `public_id`；`internal_id` 不进入 external 响应、URL、日志、制品。v4/v5 是独立 assembly 命名空间；跨版本关系必须有显式来源。发布版本、assembly 和来源在搜索结果与详情中可见。
4. **双站隔离**：`external`/`internal` 是明确选择的构建与部署边界。产物、origin、CORS、Service Worker 和缓存分别隔离；API 服务端执行授权。内部结果 `private, no-store`，不得进入共享缓存。
5. **实例隔离**：每个 SoyMutDB 实例保持自己的数据库、release、权限与审计；控制台不得把不同实例的生物记录或坐标合并。任何写操作必须同时显示目标实例和环境，远端令牌不能落在浏览器持久存储、URL 或日志。
6. **远端连接安全**：只访问经管理员登记、启用和 allowlist 校验的 HTTPS 端点；禁止用户输入任意代理 URL、重定向绕过或内网探测。远端写操作在信任配置、双重授权、审计和双实例测试完成前保持关闭。
7. **一致性与回滚**：新迁移必须有 PostgreSQL 升级/降级测试；API 形状变化同步 OpenAPI 和客户端契约；品牌和远端命令须有版本冲突处理、审计与可执行回滚。
8. **可见功能真实性**：不得用静态演示数据、吞掉异常或假成功补齐页面。未恢复的旧功能在功能矩阵标“未完成”，不可将空页面算作迁移完成。
9. **语言与可访问性**：用户可见文本从统一字典和内容字段读取；两种语言都覆盖加载、错误、空态和表单校验。核心流程支持键盘、可见焦点、合理对比度和移动端，不以截图美观替代可用性。
10. **交付门禁**：涉及身份/搜索/assembly/发布/站点边界的变更必须跑 `docs/dev/database-core-contract.md` 的 P0 矩阵；隐私测试 skip/xfail 不算通过。双站构建、静态泄漏扫描、浏览器路径和部署健康检查必须分别报告实际结果。
11. **端口与配置**：`8000` 留给其他服务；新默认 API 端口为 `8010`，环境覆盖能力保留。更改配置时逐调用链核对，不做不审查的全仓替换；文档、容器、代理、监控和脚本必须一致。
12. **CI 单一实现**：`.cnb.yml` 保持交付主流程，GitHub 工作流只调用仓库脚本。新增验收放入共享脚本，验证与发布分离，PR 不持有发布密钥。测试环境缺前置条件时报告 `SKIPPED` 原因，不能记为通过。

## 架构优化目标与边界

架构优化先解决迁移产生的耦合和权限风险，不引入新权威存储，也不为视觉重做改写核心数据模型。

```text
external Vue ─┐
              ├─ typed API client ── local SoyMutDB API ── PostgreSQL (权威)
internal Vue ─┘             │                      ├─ ClickHouse (投影)
                            │                      ├─ MinIO (对象)
admin Vue ── 管理 BFF/API ──┤                      └─ Redis (缓存/队列)
             │              └─ 实例注册表 + 授权 + 审计
             └─ 受限实例连接器 ── remote SoyMutDB API (独立数据与权限)
```

1. **前端分层**：两套 Vue 应用分别保留路由/视图、领域状态、typed API client 和设计系统。把共享语义色、排版、组件行为与 i18n 字典放在明确的共享包/入口；应用只放站点差异和页面组合。API 请求不得散落在组件中，也不得复制一套与 OpenAPI 不符的 DTO。
2. **数据库优先的信息架构**：公共首页从标识符搜索进入结果和详情；搜索/表格统一筛选、分页、来源、assembly/release 显示。管理端按任务流组织导入→验证→发布→审计。设计优化以实际数据量、键盘导航和窄屏可读性为准，沿用 React 浅色科学绿基线再迭代。
3. **控制面与数据面分离**：本地 API 的实例注册表只保存连接元数据与健康摘要；各实例的生物数据、发布状态和管理命令留在本实例 API。管理 BFF 只暴露明确列出的远端管理能力，校验角色、目标和 schema/协议版本，并给每次调用关联审计 ID。
4. **多实例连接器**：为 local 与 remote 定义相同的只读能力接口和明确的写能力开关；远端采用服务间凭据、固定目标解析、超时/大小限制、熔断和可观测错误。实例切换先取消旧请求并清理敏感状态；查询键包含 instance、site variant、release、assembly、query、filters、分页及权限上下文。
5. **品牌配置链**：管理设置→PostgreSQL 版本化记录→受控公开品牌快照→Vue 运行时标题/图标→静态 HTML/manifest 发布制品。品牌读取失败时使用安全的已发布快照，不把内部设置或媒体源地址泄露到 external。
6. **契约和运维**：路由/API/端口和配置源清单从代码生成或定期校验，写入 Wiki；健康检查分本机 API、依赖、实例连接和关键业务路径。每个架构变更都记录替代方案、兼容性、数据迁移、回滚触发条件和验收指标。

## 执行顺序

执行前先做 **Gate 0：保留改动核验**：记录当前源码、未追踪文件和工作树差异；确认缺失页面引用、未完成迁移/API 字段及受影响测试。把每项标成“已完成待验”“半成品”“未开始”，再确定可构建基线。不得为让构建通过而静默删除保留的改动。随后按 BUG 台账先处理 P0，再处理 P1；每个阶段复跑单变量消融，避免同时改样式、API 和缓存导致归因失效。

### A. 恢复迁移门禁与基础设计语言

1. 两套应用恢复同一套语义色、字体、间距和焦点状态映射；优先沿用 React 的浅色科学绿，而非重新生成一套暗色仪表盘视觉。对照 390、768、1024、1440px 截图和关键计算样式。
2. 建立 React→Vue 路由/功能清单。公共站核对首页、全局搜索、基因/变异/突变系、工具、详情、登录；管理端核对 dashboard、导入、新闻、发布、设置、媒体、页面编辑等。旧深链必须可用或显式重定向；缺失功能不能以空白页面或无说明的 404 代替。
3. 浏览器门禁同时检查 HTML→CSS/JS 资源请求、真实 HTTP CSP、Service Worker 缓存、桌面/手机布局和交互。子路径部署要检查 `VITE_BASE_URL`、HTML asset href 与响应 `Content-Type`。
4. 设计评审可使用 `ui-ux-pro-max`、`ui-design-system` 与可用的界面设计插件生成布局候选和可访问性检查清单；最终选择必须由 React 功能基线、数据库核心契约和真实浏览器任务完成率决定。保存桌面/手机前后截图及取舍理由。

### B. 公共站的视觉、功能和语言恢复

1. 恢复居中的品牌/标识搜索首屏、基因/变异/突变系实体入口、分组工具卡片与资源区；新闻只显示真实发布数据，加载、失败、空结果各有独立状态。React 旧版本的演示新闻不得回流到生产。
2. 恢复分组导航、移动抽屉、键盘关闭与焦点、所有原有入口；登录路由不包公共页眉页脚。统一组件密度、可点击区域和错误/加载状态。
3. 所有可见文案、按钮、占位符、表头、错误、空态、页面标题、图标辅助文本从当前 locale 字典取值。专业缩写和稳定基因标识可保留原样；其他英文句子不得出现在中文模式，其他中文句子不得出现在英文模式。新闻等数据字段按当前语言选对应字段并定义缺失语言的显式回退标记。
4. 搜索保留 site variant × release × assembly × query × filters 的缓存键，保留无 URL 结果不可点击、匿名不暴露内部编号、外站只显示已发布记录。恢复外部来源的错误/健康/摘要与本地结果描述。

### C. 管理端功能与站点品牌

1. 恢复管理端登录卡片和响应式侧栏，并把 React 旧路由逐项映射。优先恢复导入创建/验证/提交/详情、dashboard 真实指标、新闻双语编辑/预览/回收站，再恢复设置历史和其他编辑器；接口沿用现有 API/OpenAPI 客户端，不制造假数据或假成功。
2. 站点名称支持中英两个显示名，图标使用已存在的受控媒体上传流程和不可执行图片格式；设置存入 PostgreSQL 版本化 `system_settings`，保留审计、并发版本检查及回滚。公开读取端点按显式 site variant 提供品牌快照；internal 为私有且 `no-store`。
3. 公共站与管理端在运行时读品牌快照并更新页眉、文档标题与 favicon；构建/发布时也把对应品牌写入静态 HTML 与站点图标清单，防止首屏/搜索引擎仍看到旧名字。上传和对外返回均拒绝任意脚本/SVG、非受控外链和超限文件。

### D. 一个管理面板管理多个 SoyMutDB 实例

现有 `species_instances` 表、迁移 `0039`、管理员 CRUD API 和 TypeScript 客户端是起点；它目前只保存实例元数据，尚无远程管理通道。

1. 第一阶段实现“实例”页面：增删改查、启用状态、唯一 local 标识、站点/API/JBrowse 地址、连接状态和错误时间。实例列表与选择持久化在管理端状态；每个界面明确展示当前实例、发布版本和服务器。默认仅操作 local。
2. 远程操作走控制台 API 的受限转发服务：浏览器不直连远程 PostgreSQL/ClickHouse，也不把用户令牌写入 URL/localStorage。目标只能取自管理员已登记、启用且通过固定 HTTPS 域名/IP allowlist 的实例；不可把请求给定 URL 当作代理目标。服务间凭据放部署密钥，按实例独立轮换。允许的远程路由、HTTP 方法和角色逐项列白名单；远端再次授权。设置超时、响应体上限、重试/幂等边界、审计关联 ID 和熔断状态。
3. 控制台对每个实例使用独立的查询缓存命名空间；切换实例清除敏感旧状态。跨实例只显示注册信息与明确标注来源的聚合健康摘要，不合并生物学标识、坐标、release 或权限。任何变更必须显示目标实例与环境，发布/回滚走原有实例流程。
4. 本地管理员和远端服务间信任配置完成前，远端仅可登记、探活和跳转其管理地址，不开启写操作。通信协议、白名单、凭据轮换与失效处理通过安全审查和双实例集成测试后再开启远端编辑。

### E. 默认 API 端口改为 8010

`8000` 留给其他服务。`8010` 已在本机监听端口检查中确认当前空闲；它是 SoyMutDB 的新默认值，部署时仍允许由环境变量覆盖。逐一更新公共站/管理端 Vite 默认 API 源、无 Docker 预览、Compose 内部 API/健康检查、MCP 到 API 的地址、Dockerfile、Nginx/Cloudflare Tunnel upstream、Kubernetes、Linux systemd、Windows PowerShell、监控抓取、示例环境变量和当前运维文档。对历史测试夹具或仅用于检测禁止 `hostPort` 的 `8000` 字符串逐条判断，不做全仓盲替换。改动后检查所有调用链的请求实际抵达同一端口，并运行端口/部署契约测试。

### F. 项目 Wiki 与目录清理

在仓库内建立 `docs/wiki/`，从根 `README.md` 链接。至少包含架构与数据流、公共站/管理端功能及迁移状态、API 路由与端口、部署/备份/迁移/回滚维护方案，以及多实例信任模型。API 与端口表从当前路由、Compose、服务配置和示例环境文件核对；对尚未恢复的功能标注“计划中”，不写成已上线。

清理前先生成文件清单并分为：受版本控制的源码/证据、当前未提交修改、可再生的忽略目录、无引用的废弃文件。只清理已证实可再生且不被发布流程消费的缓存和构建输出；保留现有未提交部署脚本、`apps/web/public/fonts/`、历史 React 视觉证据和可追溯的迁移资料。删除任何受版本控制文件前须有引用扫描、对应测试和可恢复的 Git 记录。清理后重跑构建、契约测试和浏览器检查。

## 执行门禁与分工

1. **方案冻结与工作树核验**：以本文、两个迁移前 React commit、当前 API/OpenAPI 和数据库核心契约作为验收基线；先登记保留的半成品改动及其构建状态，再列清每个旧路由、页面状态和部署变体的映射。
2. **消融先行**：先在未改动的产物上跑 CSS、CSP、API 故障、语言、组装选择、子路径与实例切换的单变量实验，留下指标、截图和日志；只有故障归因清楚才实施对应修复。
3. **分区实施**：公共站与语言、管理端、后端品牌/多实例契约、端口/交付、Wiki/清理分别拥有互不重叠的文件区。共享客户端与 locale 字典指定唯一编辑者，其他分区只提交字段需求。每个分区先做最小行为回归测试，再改实现并复测。
4. **集成审计**：逐项检查 React 功能差异、双语可见文案、权限/缓存隔离、实例来源标识、端口一致性、静态产物和浏览器表现。未通过与未执行项目保留在缺口清单，不把局部成功称为迁移完成。
5. **发布判定**：两套站点与两种 site variant、PostgreSQL 升降级、OpenAPI/client、核心隐私矩阵、部署健康检查及浏览器流程均有证据之后，才允许切换正式发布；远端写操作另设独立安全门禁。

## 分阶段消融实验与验收

每次只改一个因素，在两套应用相同浏览器与宽度下记录 CSS 状态、关键计算样式、控制台、截图、交互结果。

| 因素 | 对照 | 判别结果 |
| --- | --- | --- |
| CSS 资源 | 正常 / 阻断 CSS | 判断部署资源丢失是否足以复现“全部无布局” |
| CSP | 当前策略 / 移除 `unsafe-inline` | 判断运行时 Antdv 样式是否被 CSP 单独阻断 |
| 语义色映射 | 无 `@theme` / 恢复映射 | 判断透明背景/黑色文字来自迁移时 token 丢失 |
| API | 健康模拟 / 不可达 | 错误状态应可见，不得伪装成真实空结果；布局不应变化 |
| 语言 | zh / en | 逐页扫描可见文字与表格；专业缩写列白名单 |
| 站点实例 | local / remote 健康 / remote 超时 / remote 未授权 | 确认状态隔离、目标提示、无跨实例缓存与无越权 |

首轮本机实验已证明：阻断 CSS 使公共站 `.min-h-screen` 从 `flex` 变 `block`、任务从 `grid` 变 `block`，管理端登录表单从 384px 变约 1264px；单独收紧 CSP 时 Tailwind 布局仍在，但 Antdv 按钮从 32px 变 24px 且出现多条 inline-style 拦截。两种故障机制必须分开修。

完成标准：两套产物构建、类型/单元测试、API 契约和有意义的浏览器路径通过；数据库核心矩阵与外站泄漏负例通过；React 旧关键路由有明确映射；中英截图和文案扫描通过；品牌修改在两站和静态发布内容中一致；两实例集成环境下的探活、切换、权限及失败恢复通过。记录每项通过、失败或未验证，不以部分测试代替整体验收。
