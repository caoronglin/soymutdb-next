## 目标

SoyMutDB 是生物信息学数据库。核心体验是标识符搜索、结构化结果、筛选分页、实体详情和可追溯的数据关联。实现突变体公开/内部两种编号、v4/v5 独立版本搜索，以及 external/internal 两套访问边界。不得用首页美化、静态卡片或临时关闭功能替代这些能力。

## 执行方式

1. 确认工作区、分支、未提交改动、运行环境和分配范围。保留已有工作；不假定脏工作区的修改属于自己。
2. 完成 T0：核验相关调用链、模型与外键、发布/权限规则、生成客户端和测试入口。写出实际缺口、契约版本、修改清单、依赖及验收项。
3. 区分已确定业务规则、工程选择和缺失业务输入。工程内的可逆选择自主完成；编号签发、内部业务编号含义等无法从资料确定时，只暂停依赖该决定的部分，继续独立工作。
4. 按 T1→T2→T3→T4→T5 依赖推进。已有正确实现直接复用；发现实际缺陷时先建立能捕获它的测试，再做聚焦修复。不要无关重构或引入替代框架。
5. 同步模型、迁移、服务、API、OpenAPI、客户端及调用方。身份或版本变更必须检查导入、worker、投影、导出和关联数据，不止修改页面。
6. 先跑受影响的窄测试，再跑契约、类型检查、构建和关键端到端测试。记录环境、命令、退出码和真实通过/失败/跳过数。无法启动与断言失败分别记录。
7. 持续执行已授权工作，不在写完计划或骨架后宣称完成。需要外部输入或权限时明确具体阻碍和已尝试的安全替代，不重复无效命令。

## 协作

默认由一个执行实例顺序完成任务。仅在用户明确授权且环境提供真实委派能力时使用子智能体；不得编造派发、模型、消息或完成状态。
并行时按交接文档分为 A 数据/API、B 客户端/UI、C 隔离/测试，统一契约版本。每个共享文件只有一个写入者；迁移链归 A，客户端生成归 B。总控处理跨任务依赖、冲突和最终验收。

## 进度与恢复

维护 `docs/dev/database-execution-status.md`，存在时先阅读并保留历史证据；不存在时创建。记录：任务范围、基线、契约决定、文件归属、任务状态、测试证据、阻碍和下一步。
任务状态仅用 NOT_STARTED、IN_PROGRESS、BLOCKED、IMPLEMENTED_UNVERIFIED、VERIFIED。只有相关验收通过才设 VERIFIED。
测试证据绑定 commit；存在未提交改动时另记录相关 diff 摘要和运行时间。代码之后变化，受影响证据失效并重跑。
长任务中简短报告有意义的进展、发现与下一步；上下文恢复后先核对状态和实际文件，不重新执行已完成且未失效的工作。

关键场景未实现或未验证时，明确“部分完成，不能发布”。不要报无依据的完成百分比。
