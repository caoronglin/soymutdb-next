## 设计方案

采用版本化发布包、分阶段部署和证据门禁。初期以现有 Compose 部署为基础，先实现可靠的单机发布；具备多实例和流量控制后再增加百分比灰度。不得声称 Compose 自带流量灰度能力。

| 工作包 | 内容 | 交付物 | 完成条件 |
|---|---|---|---|
| D0 | 核对部署脚本、Compose、CI、迁移、双站构建和健康接口 | 当前能力与缺口表 | 每项结论有文件或运行证据 |
| D1 | 工具版本、文件系统、配置、端口、磁盘、服务连接预检 | 统一预检入口 | 错误配置提前失败，日志不泄密 |
| D2 | 网站核心流程、真实 PostgreSQL、API/client 契约和双站隔离 | 分层 CI 检查 | 所有必需检查通过 |
| D3 | 镜像 digest、静态制品、校验和、迁移兼容性和回滚目标 | 发布 manifest | 制品可校验、可追溯 |
| D4 | Compose 校验、服务启动、迁移、隔离测试数据和冒烟 | 开发部署入口 | 搜索到详情的真实链路通过 |
| D5 | 候选发布包的代理、Cookie、缓存、Worker 和双站验证 | 预发布验收报告 | 全部预发布门禁通过 |
| D6 | 部署锁、兼容迁移、应用切换、发布观察和应用回滚 | 生产发布与回滚流程准备 | 在隔离环境完成恢复演练；生产执行另行授权 |

网站核心验收必须覆盖标识符搜索、筛选、分页、实体详情、稳定链接，以及 assembly、release、provenance 展示。部署脚本不能替代功能验收。

### 版本与制品

- deployment_id：一次部署的唯一标识。
- application_version：软件版本及 Git SHA。
- data_release_id：PostgreSQL 中的数据发布标识，沿用现有类型。不得将软件版本字符串写入数据库 release_id。
- 后端镜像按 digest 晋级。
- 前端制品由 environment、site_variant、data_release_id 及构建配置共同标识。只有影响构建的配置完全相同时，才允许复用同一制品；不得默认在开发、预发布、生产间复用含构建时 origin 的站点。
- manifest 至少包含代码快照、环境、站点、数据 release、镜像 digest、静态制品哈希、工具链、迁移前后版本、兼容范围、验证结果和上一可用发布包。不得记录 secrets。

### 迁移、Worker 与回滚

迁移采用扩展、回填、收缩阶段：先增加兼容结构，再做可恢复、幂等的分批回填和一致性校验，最后才收缩旧结构。按具体迁移评估锁和事务限制，不机械使用统一 SQL 模板。

Worker 新旧版本共存前必须验证消息、结果和数据库兼容性；无法兼容时暂停接单并排空任务。验证重试和重复投递不会重复产生业务副作用。

应用回滚切换到上一镜像和静态制品，前提是它们兼容当前数据库。数据损坏时暂停写入，按已演练流程恢复；不得简单自动执行 downgrade。部署须具备环境级互斥锁，失败保留阶段状态、诊断和恢复步骤。

### 健康检查

存活检查只判断进程；就绪检查验证服务承诺所必需的依赖。BLAST、分析投影等可选能力分别报告状态，避免单个可选服务故障导致整站退出。发布冒烟必须通过实际代理入口，验证 API、数据库、Worker、Cookie、缓存与双站访问策略，不只读取健康接口。

## 验收与状态

### 必需验收

1. 对照 database-core-contract.md 覆盖 external/internal × public/internal 标识 × v4/v5，包含未发布数据和拒绝访问场景。
2. 使用可丢弃 PostgreSQL 验证 upgrade、适用的 downgrade、再次 upgrade，以及重复标识、孤儿引用和 assembly 一致性。不得以 SQLite 或 mock 替代。
3. 验证搜索、筛选、分页、实体详情、稳定链接和上下文展示；API 形状变更验证 OpenAPI/client 契约。
4. 验证 Worker 权威关系、ClickHouse 投影、MinIO 对象上下文、幂等性、重试和任务版本兼容。
5. 双站独立构建并校验 manifest；负向泄漏测试覆盖响应体、URL、客户端可见日志和 dist/external。扫描应使用已知内部标识及未发布哨兵等可判定证据，不以泛化字符串扫描替代访问控制测试。
6. 通过真实代理验证 Cookie、CORS、私有响应 no-store 和双站缓存隔离。
7. 根质量门禁和对应服务测试通过；记录命令、退出码及 pass/fail/skip/xfail。依赖或环境故障不得计为通过。
8. 在隔离环境演练重复部署、阶段失败恢复、应用回滚及适用的数据备份恢复；保留制品哈希、日志和恢复时间证据。

### 工作项状态

NOT_STARTED、IN_PROGRESS、IMPLEMENTED_UNVERIFIED、BLOCKED_ENVIRONMENT、FAILED、VERIFIED。

### 环境就绪标签

- DEV_READY：隔离开发环境和核心冒烟通过。
- STAGING_READY：候选制品及全部预发布必需门禁通过。
- PRODUCTION_READY：预发布验收、恢复演练、配置与制品检查全部通过；不代表获准生产部署。
- DEPLOYED：目标环境实际部署完成且部署后验证通过，必须注明环境。

数据库或隐私检查未通过时，不得标记 STAGING_READY。文档、脚本或单元测试存在不代表相应环境就绪。
