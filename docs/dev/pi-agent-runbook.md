# PI AGENT 加载与启动模板

本包提供纯文本提示词，不假定 PI AGENT 的版本、CLI 参数、自动加载文件名或子智能体支持。请用你的运行环境实际支持的系统提示词入口加载文件内容；没有读取仓库文件的能力时，需要一并提供引用文档内容。

## 加载顺序

1. 系统提示词：`docs/dev/pi-agent-system-prompt.md` 全文。
2. 硬性约束：`docs/dev/pi-agent-hard-constraints.md` 全文，接在系统提示词后或作为同等可用的任务约束提供。
3. 下述启动消息作为用户任务；工作目录设为实际仓库根目录。

提示词不提供沙箱或数据库访问控制。运行器应限制到任务工作区、隔离测试环境和必要工具；生产凭证不应注入实施实例。
本次没有改写 AGENTS.md，也没有自动配置或启动 PI AGENT。

## 推荐：单实例总控启动消息

```text
你负责执行 SoyMutDB 数据库核心能力改造。
先读取 docs/dev/pi-agent-hard-constraints.md 和 docs/dev/database-execution-handoff.md。
本轮范围：T0–T5 的本地实现、迁移编写、隔离测试与交付；不包含生产回填、生产迁移或发布。

先核对当前分支、未提交修改和运行环境，核实已有实现，再创建或更新 docs/dev/database-execution-status.md。
完成 T0 的契约与依赖整理后，继续实施已具备输入的任务，不要在仅有计划时结束。
对内业务编号含义、公开编号签发等规则优先查证现有文档和数据定义；无法确定时列出具体问题，继续无依赖工作，不编造业务规则。
采用交接方案建议的无版本按 assembly 分组检索设计；任何偏离需记录原因及影响。
默认单实例按依赖顺序执行，不自行启动额外智能体。
遵守 H01–H12，按真实测试证据更新状态。最终交付实现、测试结果、剩余阻碍和可复现命令。
```

## 可选：用户另行启动三个实例

必须先由总控完成 T0、填写契约版本与准确文件归属，再派发。以下尖括号内容必须替换，不能原样执行。模型在运行器中选择，不靠提示词改变模型。

```text
角色 A：数据/API。执行 T1、T2。
契约版本：<已冻结版本及文件>。
允许修改：<总控列出的模型、迁移、服务、schema、导入与测试文件>。
不修改客户端生成物、Web 或 C 管理的 CI/E2E 文件。
先核验双 ID 语义、Gene 跨 assembly 身份及所有引用，再实现迁移和检索授权。
向总控交付接口变化、迁移顺序、测试证据和 B/C 接入条件。
```

```text
角色 B：客户端/UI。执行 T3。
契约版本：<已冻结版本及文件>。
允许修改：<总控列出的客户端、Web、必要消费者与测试文件>。
不自行改 API schema 或迁移。API 未就绪时先做契约驱动的组件测试与设计；不把 mock 成功当联调通过。
真实接口可用后重新生成客户端，完成数据库检索、版本标签、双 ID 展示和详情/JBrowse 链路。
向总控交付生成一致性、类型检查及 UI 行为证据。
```

```text
角色 C：隔离/验证。执行 T4。
契约版本：<已冻结版本及文件>。
允许修改：<总控列出的 scripts、fixture、E2E 与 CI 文件>。
与 A 明确 API 测试文件归属，避免同时编辑。
优先编写 H01–H12 的负向用例和构建输入哨兵，待 A/B 就绪后执行完整隔离与 E2E。
报告真实失败及复现条件；不通过削弱断言、skip 或改业务代码绕过缺陷。
```

## 续跑消息

```text
继续当前任务。先读取 docs/dev/database-execution-status.md，再核对当前 diff 与最近测试证据。
保留此前已确认契约和未提交工作，恢复第一个依赖已满足的未完成任务。
代码发生变化时重验受影响项。沿用系统提示词及硬性约束；不要重做已完成且证据仍有效的任务。
```
