# SoyMutDB PPTX 逐页布局验收清单

> **目的**：以 [`pptx-layout-spec.md`](pptx-layout-spec.md) 为唯一 PPTX 解读基线，对 `docs/01.pptx` 的 7 张页面进行可复核的视觉与布局验收。
>
> **使用方式**：每次候选前端构建以 1440×900、1024×768、390×844 三个视口运行 `e2e:visual`（见 [`visual-regression.md`](visual-regression.md)）。在本清单的“结果”中记录通过/失败/不适用和证据目录。该清单检验内容层级、布局、响应式与可操作性，**不取代** G0–G16 数据/安全上线门禁。

## 1. 全局验收规则

| ID | 验收项 | 通过标准 | 证据 |
|---|---|---|---|
| GVL-01 | 无横向溢出 | 每页每视口 `scrollWidth <= clientWidth`；移动端不发生横向滚动 | 自动 JSON 指标 |
| GVL-02 | 可见主内容 | `main` 或页面主内容存在、可见，且页面正文非空 | 截图 + DOM 指标 |
| GVL-03 | 顶部壳 | 站点名/标识与主导航存在；桌面有 5 项主导航或等价菜单，移动端可通过折叠菜单访问 | 截图 |
| GVL-04 | 可读性 | 正文、表单和按钮未被固定头部/浮层遮住；文本不以省略号截断关键标签 | 截图人工复核 |
| GVL-05 | 交互命中 | 可点击导航、链接和提交按钮的可见尺寸不小于约 24×24 CSS px；移动端主要 CTA 建议 ≥44 px 高 | 自动 DOM 指标 + 截图 |
| GVL-06 | 降级策略 | 表格在窄屏可横向滚动或转为卡片，但页面根元素仍不可横向溢出；不允许不可见列悄然丢失 | 截图人工复核 |

**结果填报**：`✅ Pass` / `❌ Fail` / `⚠️ Review` / `N/A`。任何 `❌ Fail` 要附路由、视口、截图文件和复现步骤；布局与 PPTX 的合理响应式差异可标为 `⚠️ Review`，说明理由。

## 9. 已知开放项与判定边界

1. **引物设计**：PPTX 要求首页入口；当前前端若映射到 `/search/primer`，该入口应正常可达。PPTX 未定义独立的引物页面视觉，因此不将其作为 slide 级对照项。
2. **Gbrowse 名称**：验收统一使用 **JBrowse 2**，不因不再显示“Gbrowse”判失败。
3. **真实数据与外部嵌入**：无 staging 真实数据或 JBrowse URL 时，数据/iframe 不可用应记录为环境阻断；不要把环境配置失败归类为纯布局通过。
4. **首页额外 Hero**：用户已明确要求“顶部独立区块，下方才放最新动态+轮播图”；这属于当前产品要求并优先于旧 PPTX 对首页上方空间的简化表达。
